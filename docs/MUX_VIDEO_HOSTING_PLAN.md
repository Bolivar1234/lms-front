## Outcome, scope and package order

Teachers upload video inside the LMS and add manual WebVTT captions; entitled students watch signed adaptive playback. Existing external video, private audio/documents, free-preview behavior, manual completion and checkpoints remain intact. No Solana work, watch-based completion, new payment rail, auto-caption/translation/AI subsystem or general provider catalog mirror belongs to this feature.

The confirmed topology is LMS `circles.saythanks.org`, SayThanks `saythanks.org`, common authentication and LMS data in schema `lms`. The shared-db README describes staging; this does not establish production migration or identify a safe hosted write target.

## Data model, integrity and history

All feature objects below live in the selected LMS schema except the named Storage bucket. Server-owned tables enable RLS and explicitly revoke ALL table/sequence privileges from PUBLIC/anon/authenticated, including SELECT and default-privilege exposure. Revoke EXECUTE on service-only RPCs from these roles; grant only intended service/operator boundaries. Existing user-scoped restore RPCs retain narrowly reviewed caller authorization rather than being indiscriminately converted to service-only functions. Browser capability DTOs replace direct settings/provider reads.

| Object | Contract |
| --- | --- |
| `lesson_media` | UUID media/intent IDs; tenant UUID; lesson ID matching actual catalog (`bigint` in canonical lessons); nullable uploader FK, immutable non-null `request_actor_id` without auth FK; request key and canonical request fingerprint; environment/upload/asset/playback IDs; LMS state; untrusted declarations; authoritative duration/aspect ratio; error and lifecycle timestamps; once-only reservation release marker. |
| `lesson_video_source` | One row per tenant+lesson; external/mux mode; nullable selected media; monotonic generation. No row means legacy external `lessons.video_url`. A mux source with no available selection is unavailable, never implicit fallback. |
| `tenant_media_settings` | Service-only opt-in and finite pilot caps. Missing row disables hosting; active school admins cannot self-enable through `tenants` UPDATE grants. |
| `lesson_media_captions` | UUID attempt; tenant/media; language/label; private VTT path, provider track ID; caption state/timestamps; idempotency/fingerprint. Replacement is a new caption attempt; keep previous ready track until the new one is ready. |
| `lesson_media_cleanup_outbox` | Environment, opaque intent nonce and any known waiting-upload/asset/track/Storage identity, opaque owner reference, reason, attributable duration, due/retry/lease/error and completion. No parent/auth FKs. Unique cleanup identity prevents double counting/deletion jobs. |
| `lesson_media_operator_audit` | Immutable actor UUID, action, target/environment, reason and timestamp; no deletion-blocking parent/auth FKs, capability URLs or private keys. |
| `lesson_media_rate_limits` | Atomic environment+tenant+user/school+operation+window counters and bounded expiry, accessed only by service-owned functions. |
| Existing `webhook_events` | Minimal immutable verified receipt; Mux-specific due/retry/dead-letter state; provider namespace `mux:lms:<environment-id>`. Payments keep their existing contract. |

Use unique `(tenant_id,id)` on lessons and `(tenant_id,lesson_id,id)` on media before source composite FKs. Verify course+lesson+tenant scope and actual prerequisite types. Provider upload/asset uniqueness is global across tenants within the Mux environment, not tenant-local. One provider asset belongs to one LMS media row. Idempotency uniqueness is `(tenant_id,request_actor_id,request_key)` even after uploader deletion; keys are 1–128 printable ASCII characters, with UUIDs recommended. Fingerprint includes lesson, normalized declaration, source generation and operation/replaced media. A changed request under the same key returns 409.

A per-school settings-row `FOR UPDATE` lock serializes reservation accounting; a per-lesson lock serializes source/start/restart/remove. Use one consistent order (school, lesson, then media/caption rows). Missing settings fail closed. A partial unique index prevents two uploading/preparing attempts per lesson; ready/selected-media exclusion is also checked while locked. Provider calls occur outside the database transaction; durable intent and ownership exist first. Select inserts media before setting the pointer; no circular insert requires a deferrable FK. Prefer PostgreSQL 15+ column-specific `ON DELETE SET NULL (media_id)` on the pointer; verify target support. Any fallback must work for database cascades, not just app code.

A media BEFORE DELETE trigger captures owned intent/upload/asset/track/Storage cleanup in the deleting transaction. Retain pending-upload/nonce tombstones even when no asset ID is known; late owned ingest must enrich the existing cleanup identity and queue deletion, never recreate a deleted lesson/media owner. Explicit removal enqueues cleanup and stops grants before a physical cascade. Repeated paths converge by environment/provider identity; preserve tombstones. Account departure nulls uploader attribution without destroying school-owned media; immutable request/audit identity survives. Ordinary course/lesson/tenant cascades must work without disabling triggers. `seed-prod.sql` uses replica mode and is not an application deletion procedure or an authorized shared reset.

WS1 must explicitly replace the effective `public.snapshot_lesson_version()` and `public.restore_lesson_version(bigint, integer)` definitions after all prior migrations, preserving current course-author checks, AI-task removal and version semantics. The checked shared feature variant must replace the corresponding `lms` functions, qualify their dependencies and bind the actual lesson trigger to the intended schema/function. Verify `pg_get_functiondef`, signatures, owners, EXECUTE grants and trigger bindings in both disposable catalogs and the read-only hosted receipt; a search-path tweak is insufficient. The checked checkout contains two explicit CREATE OR REPLACE definitions of each function; the reported count of three and the hosted copies require catalog evidence, not an assumed history count.

Install a SQL BEFORE UPDATE guard on `lessons.video_url`: a changed URL while current source mode is hosted is rejected for direct PostgREST, RPC and service updates alike; unchanged values and unrelated text edits remain allowed. To change it, the reviewed source operation must lock the lesson, explicitly select external mode/increase generation, then perform the URL change in that transaction. Use IS DISTINCT FROM semantics for NULL changes. No caller-controlled bypass flag or trigger disabling. Restore/clone cannot bypass this invariant. Source changes must snapshot the pre-change lesson/source under the same lock before changing mode; a subsequent lesson UPDATE cannot label its old fields with the new source marker or create duplicate user versions.

Snapshots gain `video_source: {version: 1, mode, media_id}` (LMS ID only); missing marker means legacy external. Snapshot creation and source-changing operations use the same locking contract. Provider state changes do not create ordinary lesson versions. Initial restore rejects atomically when current source **or snapshot marker** is hosted, including hosted-to-external and external-to-hosted cases; an external-only restore still works. Before pilot, every active lesson renderer/DTO and transcript/question caller resolves the current source: hosted mode never reads the retained external video_url or a cached legacy YouTube transcript as if it described the selected video. Initial hosted extraction is explicitly unavailable (or an explicitly chosen lesson-text/manual-input path); external/manual behavior remains. Guard unsupported native/MCP/core readers before enabling hosted lessons for them, even while full client support remains WS6. Clone/import/export reject unsupported hosted copies visibly. Direct legacy writes cannot switch hosted mode or retain a silently active pointer. WS6 later supports round trips with a new generation, never rewinding it, and explicit unavailable historical/deleted assets.

## Authentication, access and trusted origins

Extract a shared access service from `lib/lessons/resource-download.ts`: trusted tenant/lesson/course ownership and fresh active school membership for **every** caller, then course author, school admin or actual `has_course_access` entitlement including access cutoff. Neither authorship nor entitlement bypasses inactive/removed membership; JWT role/tenant claims alone are insufficient. Enrollment is progress, not entitlement. Student grants also require published course and lesson with effective publish time reached; drafts/unpublished/scheduled content is 404 even for an enrolled student. A current active author/admin has an explicit authenticated draft-preview branch, never an anonymous preview bypass. Keep existing public resource previews separate; hosted grants require authentication in this pilot. Database errors fail unavailable, not success or fabricated absence.

All new lesson-scoped media routes use a strict tenant resolver inside `lib/media/auth.ts`: require a single unambiguous application-verified tenant context, or a verified scoped Bearer context, validate it against the authoritative lesson/course and active membership, and reject missing/conflicting contexts. Do not call `getCurrentTenantId()`/`getCurrentTenant()` for their default-school fallback or trust inbound x-tenant-id/x-user-id as verified identity. Platform origin without a scoped tenant cannot mint a lesson grant. Preserve unrelated legacy routing helpers; this is the new media boundary, not the previously blocked routing investigation.

For new media handlers, reject a Bearer header combined with any `sb-*` cookie as `mixed_credentials` before choosing an auth path. Cookie writes require verified session, JSON Content-Type and exact Origin equality to the trusted school origin; missing/wrong Origin fails. Bearer-only writes verify the token server-side, have no cookie fallback and need no browser Origin. Neither credentials means 401. Tenant membership/role comes from authoritative database records. The legacy helper's cookie-first behavior is not permission to bypass these new route checks, nor proof by itself of an existing exploit. MCP writes remain unsupported until WS6 explicitly carries end-user identity; a service key is not an upload actor.

Derive origins from verified tenant ID -> current slug and configured platform domain/scheme. Never use request Origin, Host, forwarded host or body CORS values as authority. `getTenantSiteUrl` reads headers and is not this builder. Shared school hosts follow the verified configured topology; unverified custom-domain upload returns an explicit unsupported-origin error. CI explicitly configures localhost/lvh.me. Test real Mux CORS matching; a URL parser test is not provider proof.

Canonical callback is `/api/mux/webhook` on the verified LMS platform origin, normally `https://circles.saythanks.org`. `circles` is already reserved by `lib/tenant/reserved-slugs.ts`; `NEXT_PUBLIC_PLATFORM_HOSTS` is useful explicit configuration, not required to make that reserved label non-tenant. API routes skip page locale/auth guards, but proxy host handling must still pass real signed callbacks without tenant lookup/404/redirect. Incoming tenant headers never determine webhook ownership.

These are the implementation contracts. IDs in paths/bodies are LMS IDs only. Teacher access below means verified teacher/course author or authorized active admin for the scoped lesson. All JSON responses are private/no-store; all writes use JSON, including DELETE bodies. General lesson/status DTOs omit provider IDs, upload/source URLs, credentials and raw errors. A new create handoff and an authorized playback DTO are the explicit capability exceptions; operator inventory is separately privileged.

## Canonical limits and switches

Numbers below are initial application policy, not measured Mux guarantees. Operators may lower finite pilot caps. Raising them requires reviewed configuration and capacity evidence. Duration and declared size checks before upload are guidance: the chosen direct-upload API does not enforce a general byte/MIME/duration ceiling on actual uploaded bytes.

| Policy | Initial contract |
| --- | --- |
| School inventory / video | 300 stored minutes / 90 minutes per video. Later approved duration maximum four hours. |
| Attempts / pending | Five **new attempts** per school per UTC day; two pending per school; one per lesson. Duplicate keys/refusals cost no new attempt. A reserved attempt consumes its daily count even if cancellation follows. |
| File declaration | MP4/MOV browser guidance, 2 GiB declared-byte maximum; server verifies actual track/duration after ingest. No hard provider byte-limit promise. |
| Upload expiry / adapter | 3,600 seconds; SDK create retries disabled (`maxRetries: 0`), 10-second create timeout. Other worker calls bounded to three seconds each with explicit retry policy. |
| Request body | Ordinary media JSON 16 KiB; decoded caption UTF-8 2 MiB; raw caption JSON 12 MiB + 16 KiB; raw webhook 1 MiB. Enforce actual streamed bytes, irrespective of Content-Length. WS4 must configure Next 16 proxy buffering (`experimental.proxyClientMaxBodySize`, initially 13 MiB) and verified reverse-proxy/ingress transport ceilings above the raw caption route bound; the default 10 MiB buffer can truncate valid escaped JSON. serverActions.bodySizeLimit does not configure route handlers. Keep route streaming caps authoritative and prove 413 through the production-mode proxy for over-limit requests. |
| VTT complexity | At most 10,000 cues, 16 KiB UTF-8 per cue; duration bounds; conservative supported cue settings only. |
| Playback throttle | Atomic 30 grants/user/10 minutes AND 1,200 grants/school/10 minutes; separate environment+operation keys. |
| Start/restart throttle | Ten requests/user/minute AND 30/school/minute, in addition to daily reservations. |
| Caption-write throttle | Ten/user/10 minutes AND 30/school/10 minutes, in addition to media access/body checks. |
| Callback time / clock | Target durable acknowledgement under two seconds, provider attempt deadline five seconds; SDK freshness tolerance 300 seconds plus explicit maximum future skew 30 seconds. |
| Worker batch / retries | At most 25 items and ten seconds/run; start no new item after budget. Backoff 60 seconds doubling to one hour + 0–30 seconds jitter; 48 failed attempts then dead letter/manual recovery. Provider's 24-hour retry window is independent. |
| Source-fetch / preparing | Signed caption-source TTL 900 seconds (must be proven live); max three confirmed ingest retries with refreshed URL; preparing older than 30 minutes alerts/reconciles; six-hour unresolved preparation becomes processing_timeout/errored and queues owned cleanup while inventory stays counted. |
| Retention / monitoring | Retired replacement held 24 hours; at least five minutes beyond greatest issued-token lifetime. Three missed minute ticks + two-minute deployment grace alerts. |

`MUX_PROVIDER_ENABLED` and `tenant_media_settings.enabled` default false and gate create, hosted activation and grants/renewals after access checks. `MUX_ASSET_DELETION_ENABLED` independently gates **all destructive provider/Storage cleanup**, default false until a controlled cleanup drill. Caption/source status and authenticated removal remain available when hosting is off; new caption ingest is gated. Verified receipt persistence, replay/reconciliation and the scheduler remain alive. Re-enabling reconciles owned uncertain rows before accepting uploads. Flag-off does not revoke existing signed tokens or select an old external URL. Database school flags/plan state are read fresh for each privileged operation, with no process-global positive cache. Global environment flags require redeployment of every serving replica; partial rollouts keep old behavior until old replicas are drained. Record observed propagation and never promise instantaneous cluster-wide flag changes. New grants stop only once the relevant updated state is enforced; previously minted capabilities follow the bounded token window below.

Rate budgets use fixed UTC windows of the stated length. The shared Postgres limiter atomically checks both budgets in one function, and consumes neither when refusing; store errors fail 503. Expired rate-window rows are swept. It is throttling, not a per-view session ledger. Quotas lock settings/lesson rows and count provider-confirmed stored inventory plus the full effective per-video maximum for every pending reservation, independent of client-declared duration. Reject admission if this conservative reservation does not fit. Replace it with verified duration under the same lock only after authoritative ingest validation; oversized assets fail validation and retain attributable usage until confirmed cleanup. Deduplicate inventory/outbox by environment+asset ID; deleting/rejected assets count until confirmed absent. Cancel/absence releases pending capacity once, never refunds daily attempts. Compute UTC day bounds explicitly as `(date_trunc('day', now() AT TIME ZONE 'UTC') AT TIME ZONE 'UTC')`; test non-UTC sessions and midnight.

## Upload ownership, recovery and state

Use lazily initialized `@mux/ts` (reviewed 15.6.1; pin/revalidate at implementation), Mux Player React and a pinned uploader/UpChunk package. Disabled deployments build without credentials; callback secrets remain independent of flags. A server-only adapter owns SDK/signature/JWT/error/timeout behavior. Reuse narrow licensed/reference patterns, not another product's auth model.

Reserve owned intent and immutable request fingerprint before Mux creation. Pass signed playback policies, basic quality and 1080p resolution (verify eligibility live), exact server-derived CORS, upload timeout and opaque intent/media/school billing references. The school billing reference is a random server-owned attribution identifier mapped in LMS, never an email/name, secret, capability or public school profile. Validate passthrough/meta limits against the pinned SDK. Verify event environment, server-owned nonce and provider identity; passthrough alone never grants ownership.

Only the original successful create response with a valid optional URL returns that handoff. Never persist/log the URL or return it on duplicate requests. Retrieval's optional URL is not a recovery dependency. Missing create URL retains bound intent and returns `handoff_unavailable`; create timeout/failed bind returns uncertain state, retains quota/history and does not trigger blind SDK retries. Bounded environment-scoped upload listing uses credentials, pagination and exact opaque correlation; exhausting page/time budget means unknown, not absence. Initial bound is five pages/ten seconds per uncertain intent per run; retain and alert/manual-reconcile if unresolved after its expiry plus 15 minutes. No adoption of unrelated SayThanks inventory.

While the page retains File+URL, chunk progress/pause/retry can resume. Refresh recovers status, not File or URL. Explicit restart uses a new key only after old waiting upload cancellation or authoritative absence is confirmed; cancellation can lose to ingest, returning processing with no new create. Serialize concurrent restarts and removal; keep all attempt tombstones. Pilot upload is refused while ready/selected hosted media exists; teacher removes first. Later overlapping replacement is WS6.

| LMS state | Allowed transitions and source effect |
| --- | --- |
| `uploading` | `preparing` on owned upload/asset binding; `ready` may arrive first after authoritative validation; confirmed cancel/failure/expiry -> `errored`. Uncertain creation remains uploading with a safe recovery code. |
| `preparing` | `ready` after actual video/duration/policy checks; confirmed failure -> `errored`. |
| `ready` | Late preparing/error cannot regress it; owned removal -> `deleting`. Authoritatively confirmed provider asset deletion/not-found revokes current availability, increases source generation and transitions to `deleted` only after required cleanup/accounting; transient failures never count as absence. |
| `errored` | No automatic resurrection/selection; restart is a new attempt; cleanup -> `deleting`. Over-limit/non-video rejection records `validation_rejected` and queues cleanup. No separate undefined “quarantine” state. |
| `deleting` | `deleted` only on provider delete/not-found and required cleanup confirmation. Late ready never reselects. |
| `deleted` | Tombstone, no revival. |

Polling/recovery is explicit: each maintenance tick sweeps bound waiting uploads using retrieve status even if no webhook arrives; teacher status may schedule the same work without performing unbounded provider calls. Verified timed_out/cancelled without an asset becomes errored and releases pending capacity once; a retrieval 404 alone cannot resolve a create that never returned an upload ID. Preparing older than 30 minutes alerts; after six hours mark errored with `processing_timeout`, stop automatic selection and queue owned cleanup, retaining inventory until provider absence. Mux `waiting`, `asset_created`, `cancelled`, `timed_out`, etc. are adapter inputs, not alternative LMS states. Caption states are `pending`, `ready`, `errored`, `deleting`, `deleted`. ## Playback, renewal and history

After fresh access/source/readiness/flag/rate checks, sign stateless RS256 tokens with subject=playback ID, key ID and audiences `v` video/captions, `t` thumbnail, `g` GIF, `s` storyboard. Do not mint DRM `d`. No playback-session table, per-grant row lock, watch ledger or `last_playback_grant_expires_at`. General DTOs never expose provider identity; an authorized player necessarily receives signed playback capability.

Normal TTL is 600 seconds plus 0–30 seconds positive jitter, independent of video duration, with a maximum capability lifetime of 630 seconds from mint. This replaces the former duration-plus-900 policy (up to 107 minutes for the pilot). Retention/key rotation allow at least 300 seconds beyond the greatest TTL actually issued, including any older deployment tokens; a new policy cannot shorten already-issued grants. Renew through the same endpoint with lead `min(120,max(15,floor(ttl/4)))` seconds and on background return; preserve pause/playhead. Removing membership, disabling a school or changing entitlement prevents new grants once fresh state/replicas enforce it, but issued tokens may remain usable until expiry; buffered/downloaded media cannot be recalled. No immediate per-user revocation claim. Failed access shows access-ended; temporary failure retries boundedly only while the existing grant remains valid. An expired grant requires reauthorization/reload with explicit resume.

Same-media token rotation must keep stable media/generation identity and preserve the checkpoint scheduler state. Do not key/remount the player on token changes. If the SDK reloads, perform one internally controlled continuity restore of the previously observed playhead and paused state without treating its reset/restore events as user seeks or re-firing an already-active marker. This internal restore cannot create completion or disable ordinary seek gates; initial local resume still clamps to the earliest unfinished required checkpoint. Test retokening before/at/after a pending marker, a completed marker, genuine seeking and source-generation changes against the actual existing scheduler.

The accelerated drill uses **server-only staging fixture configuration** from the environment table: 120-second TTL, no jitter, only the exact disposable fixture tenant, staging stage and verified staging identities. Normal authenticated mint and renewal routes apply it for that fixture; callers cannot supply TTL. Production/invalid/incomplete override configuration fails startup. Ordinary schools always use normal TTL. Prove real decoded frames across expiry and background return; changing player props is not proof. Local/CI renewal tests use the same paired fixture policy with `MUX_DEPLOYMENT_STAGE=staging`, a synthetic disposable fixture tenant and loopback adapter on an actual local production-mode app. Assert the real 120-second grant/renewal route schedule, including expired/denied cases; cryptographic unit checks may use a fake clock. This proves app renewal wiring, not decoded Mux frames. Deployed staging uses real Mux and never the loopback seam. No production override, test query parameter or globally shortened school tokens.

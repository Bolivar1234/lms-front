## Outcome, scope and package order

Teachers upload video inside the LMS and add manual WebVTT captions; entitled students watch signed adaptive playback. Existing external video, private audio/documents, free-preview behavior, manual completion and checkpoints remain intact. No Solana work, watch-based completion, new payment rail, auto-caption/translation/AI subsystem or general provider catalog mirror belongs to this feature.

The confirmed topology is LMS `circles.saythanks.org`, SayThanks `saythanks.org`, common authentication and LMS data in schema `lms`. The shared-db README describes staging; this does not establish production migration or identify a safe hosted write target.

## Data model, integrity and history

All feature objects below live in the selected LMS schema except the named Storage bucket. Server-owned tables enable RLS and explicitly revoke PUBLIC/anon/authenticated writes, including default-privilege exposure. Browser capability DTOs replace direct settings/provider reads.

| Object | Contract |
| --- | --- |
| `lesson_media` | UUID media/intent IDs; tenant UUID; lesson ID matching actual catalog (`bigint` in canonical lessons); nullable uploader FK, immutable non-null `request_actor_id` without auth FK; request key and canonical request fingerprint; environment/upload/asset/playback IDs; LMS state; untrusted declarations; authoritative duration/aspect ratio; error and lifecycle timestamps; once-only reservation release marker. |
| `lesson_video_source` | One row per tenant+lesson; external/mux mode; nullable selected media; monotonic generation. No row means legacy external `lessons.video_url`. A mux source with no available selection is unavailable, never implicit fallback. |
| `tenant_media_settings` | Service-only opt-in and finite pilot caps. Missing row disables hosting; active school admins cannot self-enable through `tenants` UPDATE grants. |
| `lesson_media_captions` | UUID attempt; tenant/media; language/label; private VTT path, provider track ID; caption state/timestamps; idempotency/fingerprint. Replacement is a new caption attempt; keep previous ready track until the new one is ready. |
| `lesson_media_cleanup_outbox` | Environment, provider asset/track or Storage path, opaque owner reference, reason, attributable duration, due/retry/lease/error and completion. No parent/auth FKs. Unique cleanup identity prevents double counting/deletion jobs. |
| `lesson_media_operator_audit` | Immutable actor UUID, action, target/environment, reason and timestamp; no deletion-blocking parent/auth FKs, capability URLs or private keys. |
| `lesson_media_rate_limits` | Atomic environment+tenant+user/school+operation+window counters and bounded expiry, accessed only by service-owned functions. |
| Existing `webhook_events` | Minimal immutable verified receipt; Mux-specific due/retry/dead-letter state; provider namespace `mux:lms:<environment-id>`. Payments keep their existing contract. |

Use unique `(tenant_id,id)` on lessons and `(tenant_id,lesson_id,id)` on media before source composite FKs. Verify course+lesson+tenant scope and actual prerequisite types. Provider upload/asset uniqueness is global across tenants within the Mux environment, not tenant-local. One provider asset belongs to one LMS media row. Idempotency uniqueness is `(tenant_id,request_actor_id,request_key)` even after uploader deletion; keys are 1–128 printable ASCII characters, with UUIDs recommended. Fingerprint includes lesson, normalized declaration, source generation and operation/replaced media. A changed request under the same key returns 409.

A per-school settings-row `FOR UPDATE` lock serializes reservation accounting; a per-lesson lock serializes source/start/restart/remove. Use one consistent order (school, lesson, then media/caption rows). Missing settings fail closed. A partial unique index prevents two uploading/preparing attempts per lesson; ready/selected-media exclusion is also checked while locked. Provider calls occur outside the database transaction; durable intent and ownership exist first. Select inserts media before setting the pointer; no circular insert requires a deferrable FK. Prefer PostgreSQL 15+ column-specific `ON DELETE SET NULL (media_id)` on the pointer; verify target support. Any fallback must work for database cascades, not just app code.

A media BEFORE DELETE trigger captures owned asset/track/Storage cleanup in the deleting transaction. Explicit removal enqueues cleanup and stops grants before a physical cascade. Repeated paths converge by environment/provider identity; preserve tombstones. Account departure nulls uploader attribution without destroying school-owned media; immutable request/audit identity survives. Ordinary course/lesson/tenant cascades must work without disabling triggers. `seed-prod.sql` uses replica mode and is not an application deletion procedure or an authorized shared reset.

Snapshots gain `video_source: {version: 1, mode, media_id}` (LMS ID only); missing marker means legacy external. Snapshot creation and source-changing operations use the same locking contract. Provider state changes do not create ordinary lesson versions. Initial restore rejects atomically when current source **or snapshot marker** is hosted, including hosted-to-external and external-to-hosted cases; an external-only restore still works. Before pilot, every active lesson renderer/DTO and transcript/question caller resolves the current source: hosted mode never reads the retained external video_url or a cached legacy YouTube transcript as if it described the selected video. Initial hosted extraction is explicitly unavailable (or an explicitly chosen lesson-text/manual-input path); external/manual behavior remains. Guard unsupported native/MCP/core readers before enabling hosted lessons for them, even while full client support remains WS6. Clone/import/export reject unsupported hosted copies visibly. Direct legacy writes cannot switch hosted mode or retain a silently active pointer. WS6 later supports round trips with a new generation, never rewinding it, and explicit unavailable historical/deleted assets.

## Authentication, access and trusted origins

Extract a shared access service from `lib/lessons/resource-download.ts`: trusted tenant/lesson/course ownership and fresh active school membership for **every** caller, then course author, school admin or actual `has_course_access` entitlement including access cutoff. Neither authorship nor entitlement bypasses inactive/removed membership; JWT role/tenant claims alone are insufficient. Enrollment is progress, not entitlement. Keep existing public resource previews separate; hosted grants require authentication in this pilot. Database errors fail unavailable, not success or fabricated absence.

For new media handlers, reject a Bearer header combined with any `sb-*` cookie as `mixed_credentials` before choosing an auth path. Cookie writes require verified session, JSON Content-Type and exact Origin equality to the trusted school origin; missing/wrong Origin fails. Bearer-only writes verify the token server-side, have no cookie fallback and need no browser Origin. Neither credentials means 401. Tenant membership/role comes from authoritative database records. The legacy helper's cookie-first behavior is not permission to bypass these new route checks, nor proof by itself of an existing exploit. MCP writes remain unsupported until WS6 explicitly carries end-user identity; a service key is not an upload actor.

Derive origins from verified tenant ID -> current slug and configured platform domain/scheme. Never use request Origin, Host, forwarded host or body CORS values as authority. `getTenantSiteUrl` reads headers and is not this builder. Shared school hosts follow the verified configured topology; unverified custom-domain upload returns an explicit unsupported-origin error. CI explicitly configures localhost/lvh.me. Test real Mux CORS matching; a URL parser test is not provider proof.

Canonical callback is `/api/mux/webhook` on the verified LMS platform origin, normally `https://circles.saythanks.org`. `circles` is already reserved by `lib/tenant/reserved-slugs.ts`; `NEXT_PUBLIC_PLATFORM_HOSTS` is useful explicit configuration, not required to make that reserved label non-tenant. API routes skip page locale/auth guards, but proxy host handling must still pass real signed callbacks without tenant lookup/404/redirect. Incoming tenant headers never determine webhook ownership.

## HTTP routes and DTOs

These are the implementation contracts. IDs in paths/bodies are LMS IDs only. Teacher access below means verified teacher/course author or authorized active admin for the scoped lesson. All JSON responses are private/no-store; all writes use JSON, including DELETE bodies. General lesson/status DTOs omit provider IDs, upload/source URLs, credentials and raw errors. A new create handoff and an authorized playback DTO are the explicit capability exceptions; operator inventory is separately privileged.

| Method and route | Auth / request | Successful result |
| --- | --- | --- |
| POST `/api/lessons/:lessonId/media/uploads` | Teacher; `{requestKey, expectedGeneration, file:{name,mimeType,declaredBytes,declaredDurationSeconds}}` | 201 `created` with mediaId/state/generation and one-time `{url,expiresAt}`; 200 `already_created` with safe status only; 202 `create_uncertain`/`handoff_unavailable` without URL. |
| GET `/api/lessons/:lessonId/media/:mediaId` | Teacher | 200 mediaId/state/generation, safe errorCode, retry/restart capabilities, caption states; no retrieved upload URL. |
| POST `/api/lessons/:lessonId/media/:mediaId/restart` | Teacher; new requestKey, expectedGeneration and declaration | 201 new attempt only after confirmed old cancellation/absence; otherwise 202 `processing`/`create_uncertain`, or an idempotent safe result. |
| PUT `/api/lessons/:lessonId/media/source` | Teacher; `{mode,mediaId?,expectedGeneration}` | 200 safe source DTO after compare-and-swap. Mux selection requires owned ready media and flags; explicit external selection preserves the legacy URL and queues former hosted media removal under pilot rules. |
| DELETE `/api/lessons/:lessonId/media/:mediaId` | Teacher; `{expectedGeneration}` | 202 `deleting` plus safe status; repeated removal converges. Source becomes unavailable if no explicit external choice. |
| POST `/api/lessons/:lessonId/media/:mediaId/captions` | Teacher; `{requestKey,language,label,vtt,expectedCaptionId?}` | 202 captionId/state; duplicate fingerprint returns its safe status. Ready asset required. |
| DELETE `/api/lessons/:lessonId/media/:mediaId/captions/:captionId` | Teacher; `{}` | 202 caption cleanup queued. |
| GET `/api/lessons/:lessonId/media/playback` | Authenticated shared access gate | 200 `{mediaId,generation,playbackId,tokens:{video,thumbnail,storyboard,gif},issuedAt,expiresAt,renewAfter,captionLanguages}`. No provider asset/upload IDs or VTT source URL. Same endpoint renews. |
| POST `/api/mux/webhook` and rotation alias `/api/mux/webhook/next` | Raw Mux signature, no session; bounded receipt | 200 accepted/duplicate/irrelevant after durable receipt. Alias shares the same ingest/dedupe handler. |
| GET `/api/cron/mux-reconcile`, GET `/api/cron/mux-cleanup` | Scoped maintenance Bearer secret | 200 bounded counts, oldest-pending age and outcome, never payloads/capabilities. |
| GET `/api/platform/media` | Verified identity + fresh super-admin membership | 200 bounded owned inventory/cost/stuck-row report; provider identity allowed only in this operator DTO. |
| POST `/api/platform/media/takedown` | Verified super-admin identity; exact platform Origin and `{tenantId,mediaId?,reason,expectedGeneration?}` | 202 school disabled/owned cleanup queued, immutable audit receipt. No impersonation. |

Errors use `{error:{code,retryable},requestId}`; no raw provider messages or echoed secrets. Missing/invalid auth is 401; mixed/malformed request 400; inaccessible private lesson/media (including same-school non-entitlement) 404; authenticated feature/operator denial 403; changed idempotency key, generation conflict, existing ready media or stored-cap exhaustion 409; oversize 413; unsupported Content-Type 415; invalid declaration/VTT/origin configuration 422; request/daily-attempt throttle 429; real database/provider/store failure 503 (unexpected internal defects 500). Return bounded Retry-After/reset information for 429/temporary 503. Check access before disclosing source existence or flags. Do not change existing resource routes' 403/free-preview behavior merely to align this new API.

## Canonical limits and switches

Numbers below are initial application policy, not measured Mux guarantees. Operators may lower finite pilot caps. Raising them requires reviewed configuration and capacity evidence. Duration and declared size checks before upload are guidance: the chosen direct-upload API does not enforce a general byte/MIME/duration ceiling on actual uploaded bytes.

| Policy | Initial contract |
| --- | --- |
| School inventory / video | 300 stored minutes / 90 minutes per video. Later approved duration maximum four hours. |
| Attempts / pending | Five **new attempts** per school per UTC day; two pending per school; one per lesson. Duplicate keys/refusals cost no new attempt. A reserved attempt consumes its daily count even if cancellation follows. |
| File declaration | MP4/MOV browser guidance, 2 GiB declared-byte maximum; server verifies actual track/duration after ingest. No hard provider byte-limit promise. |
| Upload expiry / adapter | 3,600 seconds; SDK create retries disabled (`maxRetries: 0`), 10-second create timeout. Other worker calls bounded to three seconds each with explicit retry policy. |
| Request body | Ordinary media JSON 16 KiB; decoded caption UTF-8 2 MiB; raw caption JSON 12 MiB + 16 KiB; raw webhook 1 MiB. Enforce actual streamed bytes, irrespective of Content-Length. WS4 must configure Next 16 proxy buffering (`experimental.proxyClientMaxBodySize`, initially 13 MiB) and verified reverse-proxy/ingress transport ceilings above the raw caption route bound; the default 10 MiB buffer can truncate valid escaped JSON. serverActions.bodySizeLimit does not configure route handlers. Keep route streaming caps authoritative and prove 413 through the production-mode proxy for over-limit requests. |
| VTT complexity | At most 10,000 cues, 16 KiB UTF-8 per cue; duration bounds; conservative supported cue settings only. |
| Playback throttle | Atomic 30 grants/user/10 minutes AND 1,200 grants/school/10 minutes; separate environment+operation keys. |
| Start/restart throttle | Ten requests/user/minute AND 30/school/minute, in addition to daily reservations. |
| Caption-write throttle | Ten/user/10 minutes AND 30/school/10 minutes, in addition to media access/body checks. |
| Callback time / clock | Target durable acknowledgement under two seconds, provider attempt deadline five seconds; SDK freshness tolerance 300 seconds plus explicit maximum future skew 30 seconds. |
| Worker batch / retries | At most 25 items and ten seconds/run; start no new item after budget. Backoff 60 seconds doubling to one hour + 0–30 seconds jitter; 48 failed attempts then dead letter/manual recovery. Provider's 24-hour retry window is independent. |
| Source-fetch / preparing | Signed caption-source TTL 900 seconds (must be proven live); max three confirmed ingest retries with refreshed URL; preparing older than 30 minutes alerts/reconciles without blind deletion. |
| Retention / monitoring | Retired replacement held 24 hours; at least five minutes beyond greatest issued-token lifetime. Three missed minute ticks + two-minute deployment grace alerts. |

`MUX_PROVIDER_ENABLED` and `tenant_media_settings.enabled` default false and gate create, hosted activation and grants/renewals after access checks. `MUX_ASSET_DELETION_ENABLED` independently gates **all destructive provider/Storage cleanup**, default false until a controlled cleanup drill. Caption/source status and authenticated removal remain available when hosting is off; new caption ingest is gated. Verified receipt persistence, replay/reconciliation and the scheduler remain alive. Re-enabling reconciles owned uncertain rows before accepting uploads. Flag-off does not revoke existing signed tokens or select an old external URL.

Rate budgets use fixed UTC windows of the stated length. The shared Postgres limiter atomically checks both budgets in one function, and consumes neither when refusing; store errors fail 503. Expired rate-window rows are swept. It is throttling, not a per-view session ledger. Quotas lock settings/lesson rows and count provider-confirmed stored inventory plus conservative pending max-duration reservations. Deduplicate inventory/outbox by environment+asset ID; deleting/rejected assets count until confirmed absent. Cancel/absence releases pending capacity once, never refunds daily attempts. Compute UTC day bounds explicitly as `(date_trunc('day', now() AT TIME ZONE 'UTC') AT TIME ZONE 'UTC')`; test non-UTC sessions and midnight.

## Upload ownership, recovery and state

Use lazily initialized `@mux/ts` (reviewed 15.6.1; pin/revalidate at implementation), Mux Player React and a pinned uploader/UpChunk package. Disabled deployments build without credentials; callback secrets remain independent of flags. A server-only adapter owns SDK/signature/JWT/error/timeout behavior. Reuse narrow licensed/reference patterns, not another product's auth model.

Reserve owned intent and immutable request fingerprint before Mux creation. Pass signed playback policies, basic quality and 1080p resolution (verify eligibility live), exact server-derived CORS, upload timeout and opaque intent/media/school billing references. The school billing reference is a random server-owned attribution identifier mapped in LMS, never an email/name, secret, capability or public school profile. Validate passthrough/meta limits against the pinned SDK. Verify event environment, server-owned nonce and provider identity; passthrough alone never grants ownership.

Only the original successful create response with a valid optional URL returns that handoff. Never persist/log the URL or return it on duplicate requests. Retrieval's optional URL is not a recovery dependency. Missing create URL retains bound intent and returns `handoff_unavailable`; create timeout/failed bind returns uncertain state, retains quota/history and does not trigger blind SDK retries. Bounded environment-scoped upload listing uses credentials, pagination and exact opaque correlation; exhausting page/time budget means unknown, not absence. Initial bound is five pages/ten seconds per uncertain intent per run; retain and alert/manual-reconcile if unresolved after its expiry plus 15 minutes. No adoption of unrelated SayThanks inventory.

While the page retains File+URL, chunk progress/pause/retry can resume. Refresh recovers status, not File or URL. Explicit restart uses a new key only after old waiting upload cancellation or authoritative absence is confirmed; cancellation can lose to ingest, returning processing with no new create. Serialize concurrent restarts and removal; keep all attempt tombstones. Pilot upload is refused while ready/selected hosted media exists; teacher removes first. Later overlapping replacement is WS6.

| LMS state | Allowed transitions and source effect |
| --- | --- |
| `uploading` | `preparing` on owned upload/asset binding; `ready` may arrive first after authoritative validation; confirmed cancel/failure/expiry -> `errored`. Uncertain creation remains uploading with a safe recovery code. |
| `preparing` | `ready` after actual video/duration/policy checks; confirmed failure -> `errored`. |
| `ready` | Late preparing/error cannot regress it; owned removal -> `deleting`. |
| `errored` | No automatic resurrection/selection; restart is a new attempt; cleanup -> `deleting`. Over-limit/non-video rejection records `validation_rejected` and queues cleanup. No separate undefined “quarantine” state. |
| `deleting` | `deleted` only on provider delete/not-found and required cleanup confirmation. Late ready never reselects. |
| `deleted` | Tombstone, no revival. |

Source selection is a separate generation-checked transaction after metadata/access/flag validation; the worker uses the intent's expected generation and never overwrites a newer external choice. Mux `waiting`, `asset_created`, `cancelled`, `timed_out`, etc. are adapter inputs, not alternative LMS states. Caption states are `pending`, `ready`, `errored`, `deleting`, `deleted`. Player states are loading/playing/paused/retrying/access-ended/video-updated/unavailable; API outcomes such as `already_created` are not persisted media states.

## Durable webhooks and maintenance

Verify bounded raw bytes/signature/timestamp before parsing any trusted receipt. Environment mismatch or foreign provenance is never an ownership upsert. Persist a minimal immutable receipt: event ID/type, environment, created/received time, relevant upload/asset/track IDs, opaque intent correlation and sanitized error/status data required to deterministically re-fetch authoritative metadata. No raw provider object, upload URL, signed VTT URL, JWT, credentials or unnecessary viewer data. Irrelevant signed types may persist a minimal completed receipt and return 200.

Add `enqueue_mux_webhook_event` rather than using payment `claim_webhook_event` as an enqueue operation. It inserts deduped unleased due-now Mux work (attempt zero), returns durable identity, and never overwrites the first receipt. Add Mux due-state/`next_attempt_at` and dead-letter metadata without changing payment semantics. Worker claim uses due time, `FOR UPDATE SKIP LOCKED`, random lease token and fenced completion/failure. Expired leases are recoverable; business effects and source generation transitions are idempotent. Completed receipts are not business work in progress. Early events with a valid owned intent remain retryable until binding; provably foreign provenance dead-letters without creating an owner row. Dead letters retain cleanup/accounting intent for audited operator replay.

**Before any Mux receipt is written**, constrain the payment redelivery query to its positive student/platform provider allowlist **before order/LIMIT**. Its current unfiltered 25-row scan skips unknown namespaces unchanged and can repeatedly select eligible Mux rows. A separate Mux worker alone does not isolate that query; never complete Mux work through payment dispatch.

Use one host-side staging minute scheduler invoking reconcile then cleanup with a dedicated secret. At runtime prove actual route reachability, bounded duration and external heartbeat alerts. The production GitHub cron does not imply a staging schedule. Do not run both schedulers for the same target. Replay retains the original verified receipt and does not reapply inbound signature freshness to old events.

## Playback, renewal and history

After fresh access/source/readiness/flag/rate checks, sign stateless RS256 tokens with subject=playback ID, key ID and audiences `v` video/captions, `t` thumbnail, `g` GIF, `s` storyboard. Do not mint DRM `d`. No playback-session table, per-grant row lock, watch ledger or `last_playback_grant_expires_at`. General DTOs never expose provider identity; an authorized player necessarily receives signed playback capability.

Normal TTL is `max(3600, ceil(duration_seconds)+900)` plus positive jitter 0–120 seconds. A 90-minute video has maximum 6,420 seconds; a later four-hour asset maximum 15,420 seconds. Retention/key rotation allow at least 300 seconds beyond the greatest TTL issued. Renew through the same endpoint five minutes before expiry and on background return; preserve pause/playhead. For short staging tokens, renewal lead is `min(300,max(15,floor(ttl/4)))` seconds to avoid an immediate renewal loop. Failed access shows access-ended; temporary failure retries boundedly only while the existing grant remains valid. An expired grant requires reauthorization/reload with explicit resume.

The accelerated drill uses **server-only staging fixture configuration** from the environment table: 120-second TTL, no jitter, only the exact disposable fixture tenant, staging stage and verified staging identities. Normal authenticated mint and renewal routes apply it for that fixture; callers cannot supply TTL. Production/invalid/incomplete override configuration fails startup. Ordinary schools always use normal TTL. Prove real decoded frames across expiry and background return; changing player props is not proof. Never set the loopback adapter seam on staging to simulate this drill.

Initial pilot has remove-first replacement. WS6 later keeps A selected while B prepares, swaps atomically when B is ready and generation wins, and holds A for fixed 24-hour retention. Existing A tokens survive; new grants resolve B and show video-updated rather than moving A's playhead into B. No old-version renewal entitlement is implied. Local resume uses user+LMS media ID, clears on logout/account switch, does not transfer across versions/devices, and never stores capability/provider URLs. Referrer restrictions supplement access only; prove native/missing-Referer behavior before enabling them for those clients.

## Captions, UX and privacy

Manual WebVTT is included before pilot; SRT conversion, auto-captions, translation and transcript AI are deferred. Existing transcript/question endpoints must check selected source before using video_url or cached YouTube transcript/timestamps; hosted mode returns an explicit extraction-unavailable result or uses an explicitly selected lesson-text/manual path, never passes a Mux URL into the YouTube extractor. Validate actual bounded UTF-8 bytes (fatal decoding), strip initial BOM, reject NUL/unpaired-surrogate text, require WebVTT structure and finite cue times within authoritative duration. Permit valid overlapping captions; require nondecreasing start times, not arbitrary nonoverlap. Enforce cue/text/settings bounds; strip NOTE blocks and reject STYLE/REGION in this initial subset with actionable copy. Treat cue text as text, never raw HTML in transcripts/UI.

Use dedicated private bucket `lms-lesson-captions`, max 2 MiB, MIME `text/vtt`, tenant/media/caption-scoped generated paths. Global Storage SQL includes restrictive browser read/write denial for this bucket even in the presence of unrelated permissive policies. Existing `lesson-resources` is 25 MiB with restrictive policies but excludes VTT; do not widen it for this feature or namespace-rewrite global Storage SQL.

For a ready owned asset, call `video.assets.createTrack` with a fresh server-signed Storage URL, language/name, text/subtitles and appropriate closed-caption flag. The provider name must be unique within that asset: before each provider ingest call, durably reserve a fresh server-owned ingest-attempt UUID mapped to the caption row; derive a bounded unique name from it, keep the teacher display label separate, and put only that opaque ingest-attempt UUID in track passthrough. A confirmed retry uses a new ingest UUID/name even if its previous errored track still exists; retain every bound track ID for cleanup. An uncertain attempt keeps its original nonce and is reconciled before any retry. This permits same-language/same-label replacement while the old track remains ready. Reconcile a lost createTrack response against exact asset+attempt correlation before retrying. Restrict source URL origin to configured Supabase Storage; never accept an arbitrary fetch URL. The 900-second source TTL is an initial assumption requiring live timing/retry evidence. Events `video.asset.track.ready`/`errored` are SDK-documented; genuine delivery and bounded reconciliation are live gates. Keep source until confirmed track ready, then queue Storage cleanup; terminal failures also queue cleanup. Confirm failed/missing old track before bounded retry; an uncertain createTrack result is reconciled by owned track metadata/listing rather than blindly duplicated. Refresh URL only for a confirmed retry. Signed student captions use the video audience; never return the source URL.

Editor shows Upload video / External link, safe declared guidance (“MP4 or MOV; up to 2 GiB declared size and 90 minutes”), upload progress/pause/retry, preparing without an unmeasured time promise, lost-File/restart, separate Video/Captions states and available removal. Missing/processing captions warn on publish; any stricter school/course requirement still blocks publishing. Warn is not compliance certification. Provide en/es keys, keyboard CC/controls, responsive light/dark layouts, Retry/Report a problem, network-retrying versus access-ended copy, and explicit unsupported native/AI operations. Preserve current checkpoint/completion behavior. Pilot success checks are in the runbook; do not substitute a caption percentage for mandatory policy.

## Environment contract

Values apply to the verified target, not another product's deployment. NEXT_PUBLIC values must agree at build/runtime/Docker configuration. No secret values belong in Git, receipts or browser variables. Conditional Mux secrets are lazily required for their operations, so disabled external-only builds remain possible; enabled hosting fails closed when prerequisites are missing.
